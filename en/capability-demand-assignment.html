Sector-based demand assignment

Featured capability · GIS automation

The demand assignment problem

In water distribution networks with hundreds or thousands of nodes, manually assigning consumption demand to each node of the hydraulic model is time-consuming and error-prone. Consumption data is typically available as:

  • Georeferenced consumption points (service connections, meters)
  • Aggregated data by sectors or measurement zones
  • Total consumption per pipe section or administrative polygon

The QGISRed assistant automatically transforms any of these sources into EPANET nodal demands.

Assignment from consumption points

When a layer of points with consumption data for each connection or meter is available, the assistant calculates the nearest network node to each consumption point and aggregates the corresponding demand. The process considers:

  • Minimum distance to the nearest node (default criterion)
  • Weighted assignment between the two end nodes of the nearest pipe section
  • Option to exclude reservoir or pump nodes

Assignment from sectoral data

When only aggregated consumption data by sector is available (e.g., flow meter readings for each DMA or supply zone), the assistant proportionally distributes the sector demand among all nodes within that polygon:

  • Distribution can be uniform or weighted by number of connections
  • Allows combining data from different sources in the same model
  • Generates an assignment report to verify process consistency
Requirement: Consumption point layers or sectoral polygons must be in the same coordinate reference system (CRS) as the distribution network. QGISRed warns if a CRS discrepancy is detected before running the assignment.
